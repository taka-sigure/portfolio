## プロジェクト実績 (Case Studies)

### 1. ファネル分析とUX改善によるコンバージョン率向上 (CVR 1.5% → 5.0%)
- **課題**: 外部要因（SEO順位低下など）によりオーガニック流入が約1/3へ減少した局面での取り組み。流入獲得側は別部門・外部要因の比重が大きかったため、コントロール可能なフォーム側のコンバージョン最適化に注力。
- **計測基盤の修正**:
  - 当初のログにはクローラーやボットのアクセスが混入しており、CVRの分母・分子が歪んでいた。
  - 改善施策に先立ち、ボット除外ロジックの実装やGoogle Tag Manager (GTM)・Meta Pixelなどのタグ発火タイミング・カスタムイベント設計を整理し、正しい数値を計測できる土台を作成。
- **施策の変遷と学び**:
  - **施策1 (横型ステップフォーム化 / 1.5% → 2.5%)**: ヒートマップツール（Clarity）の定性ログから、既存の縦型埋め込みフォームがファーストビュー外で見られていないことを確認。1問1答形式の横型ステップフォームを設計・実装して初期改善。
  - **失敗と方針転換**: 個人情報入力ステップでの約25%離脱に対し「信頼不足」と仮説を立て、認証マーク等のトラストシグナルを追加するも有意差なし。離脱の主因は信頼性ではなく「個人情報を渡す心理的コストそのもの」と分析し、「信頼を足す」アプローチから「ユーザーへの要求を減らす（削る改善）」へ方針転換。
  - **施策2 (選択プロセスの自動化 / 2.5% → 5.0%)**: ファネル分析の結果、詳細な選択ステップの通過率が20%と低迷。「自分で細かく選びたいニーズが薄い」と仮説を立て、あらかじめ推奨候補を選択状態にして確認（Yes/No）のみに簡略化。ステップ通過率が20%から35%に改善し、最終CVRは5.0%に達した。
- **結果と検証設計**:
  - フォーム開始→送信の全体CVRは 1.5% → 5.0% へ改善（約3.3倍）。
  - 主要成約件数は前年同期比 -13% から +30% へ反転。年間億規模の売上機会損失を回避。
  - 広告キーワード固定のスプリットテストで季節性・流入質を排除し、リリース月（混在月）を除外して客観的に効果検証。

### 2. レガシーAPIの.NET 9移行とDDDリファクタリング (無停止切り替え)
- **課題**: 長年の運用でビジネスロジック・アプリ処理・インフラ処理の責務が混在し、影響範囲の把握やテストが困難になっていた.NET 6製APIの刷新。
- **背景と合意形成**:
  - コードの設計改善（DDD化）単体では事業的な優先順位が上がりづらかったため、フレームワーク（.NET 6）の公式サポート終了(EOL)というビジネスリスクと紐づけて提案し、リファクタリング工数を確保。
  - 最終目標（.NET 10 LTS）への差分を小さく抑える中継地点として、当時最新の.NET 9を採用。
- **移行設計とリスク管理**:
  - **Blue-Green型の並行構築**: インプレースでの更新は避け、.NET 9 + DDD構成の新規サービスを別系統として並行構築。フロントエンド側のルーティング切り替えで移行することで、問題発生時の即時ロールバック性を確保。
  - **データベース共有時の互換性担保**: 新旧サービスが同一のデータベース（Aurora MySQL）を参照する並行稼働期間中、マイグレーションの実行権限を新規サービス側に一本化。スキーマ変更は加算的な変更（新規テーブル、NULL許容またはデフォルト値を持つカラムの追加）に限定し、破壊的な変更は旧系統の完全廃止まで持ち込まない運用ルールを策定。
- **結果**:
  - 本番障害やダウンタイムを発生させることなく新環境への完全移行を完了。
  - ドメインロジックが独立したことで単体テストの作成が容易になり、変更容易性が向上。

### 3. 自動テスト・CI/CD環境の整備とチーム支援
- **品質・テスト自動化**:
  - フロントエンドにおいて Vitest による単体・コンポーネントテスト、Playwright による主要導線のE2Eテストを導入し、手動リグレッションテストの工数を削減。
- **CI/CDパイプライン**:
  - GitHub Actions によるビルド、静的解析、自動テスト、ステージング・本番デプロイの自動化を整備。
- **メンタリング・コードレビュー**:
  - インターン生のメンターとしてタスクの切り出し、実装の相談、設計・コードレビューを担当し、実装品質の維持と自律的な開発への立ち上がりをサポート。

### 4. 計測基盤の整備とデータ活用
- 施策評価や日常運用のためのデータ基盤整備。
- 分析ツールの数字をそのまま信用せず、ノイズ（クローラー、社内アクセス）の除去やイベント発火タイミングの正常化を先行して実施。
- SQLによるダッシュボード整備を通じて、開発者以外のメンバーも直接KPIの進捗やファネルの離脱ポイントを確認できる環境を整えた。
