## Case Studies (プロジェクト実績)

### 1. ファネル分析とUX刷新によるコンバージョン率改善 (CVR 1.5% → 5.0%)
- **課題**: 外部要因によるオーガニック流入減少に伴い、主要転換数が前年比マイナス基調に転落。
- **課題特定**: 
  - 計測データのノイズ（ボット等）を除外する基盤を先行整備し、正確な数値を可視化。
  - ユーザー行動ログ（ヒートマップ等）から、初期フォームの視認率・到達率の低さを特定。
- **施策と学び**:
  - ステップフォームへの移行により初期CVRを改善 (1.5% → 2.5%)。
  - 入力離脱に対して「要素の追加（信頼性向上）」を試みるも効果が限定的であったことから、「要求を減らす（ユーザーの心理的負荷削減）」へ方針転換。
  - ファネル離脱が顕著だった選択ステップを自動化・簡略化することで、最終CVRを 5.0% まで引き上げ。
- **成果**: 転換件数が前年同期比 -13% から +30% へ大幅反転。

### 2. イベント駆動アーキテクチャへの刷新 (AWS ECS × EventBridge)
- **課題**: 定期ポーリング（10分間隔）によるECSタスク実行構成により、処理遅延とアイドル時の無駄なタスク起動が発生。
- **設計判断**:
  - EventBridgeルールを活用し、イベント発生契機でECSタスクを即時起動するイベント駆動型へ移行。
  - 既存の.NET資産および運用・監視基盤（Datadog）を活かすためECSタスク実行方式を維持し、移行工数を最小化。
  - インフラ構成はTerraformによりコード管理・再現性を担保。
- **成果**: 処理遅延の解消および無駄なコンテナ起動コストの削減。

### 3. レガシーAPIの.NET 9移行 & ドメイン駆動設計(DDD)によるモダナイゼーション
- **課題**: 長期の機能追加により責務が混在し、ビジネスロジックの変更容易性とテスト容易性が低下。フレームワークのサポート期限到来。
- **推進・設計戦略**:
  - フレームワーク更新の節目を捉え、保守性向上を目的としたDDDリファクタリングを同時に推進。
  - インプレース更新ではなく、新規サービスとして並行構築しトラフィックを切り替えるBlue-Green方式を採用し、即時ロールバック性を確保。
  - DBを共有する並行稼働期間中は、マイグレーション実行権を一元化し、スキーマ変更を加算的な変更に限定することで無停止切り替えを実現。
- **成果**: ダウンタイムゼロでの安全な世代交代を完了。ドメイン層の分離によりテストカバレッジと開発速度が向上。

### 4. 計測の信頼性確保とデータドリブンな意思決定文化の定着
- **取り組み**:
  - 単なるダッシュボード作成にとどまらず、計測の正確性担保からビジネス指標の可視化を主導。
  - 非エンジニアメンバーが自律的にデータを参照・活用できる環境を整え、組織的なデータ活用文化を醸成。
